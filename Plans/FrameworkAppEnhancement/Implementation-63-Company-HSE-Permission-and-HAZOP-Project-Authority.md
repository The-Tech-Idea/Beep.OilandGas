## Problem and resulting behavior

HAZOP had a current-FIELD request fence but its PROJECT tables had no reviewed row authority. Study reads could not succeed. Its mappings silently ignored orphan conditions, interpreted absent status as OPEN, cast fractional/oversized sequences, selected ambiguous nodes, accepted JSON objects without explicit deviation/consequence, and substituted a study ID for a missing recorded name. Missing update targets could return void success. The existing app-owned HSE.View permission was not required by the incident row-policy path.

The existing policy now supports bounded reads for HAZOP PROJECT, PROJECT_COMPONENT, PROJECT_STEP, PROJECT_CONDITION and PROJECT_STATUS. Actual GetStudiesAsync, GetNodesAsync and GetSummaryAsync read recorded study/node/deviation/status facts. Missing or inconsistent facts refuse interpretation. Every supported incident and HAZOP table now additionally requires current selected-company HSE.View permission sourced through the existing app RBAC gateway. FIELD inheritance and data entitlement remain independent prerequisites. IdentityServer remains authentication-only.

## Actual HAZOP interpretation

The service verifies integer positive sequences within the public int contract, unique node IDs/sequences, recorded node names and exact ordinal study/node/condition associations. Every condition must belong to one actual node in this study. Every deviation must have one explicit supported recorded OPEN/ACTION_REQUIRED/CLOSED status, matching its exact node and persisted status identity, with a recorded UTC effective date. Orphan or missing statuses cannot disappear from counts or become OPEN. The existing status-ID format is invariant under culture; it matches recorded state after node authority is proved and does not establish authorization.

Condition payloads must be bounded JSON objects with exactly one nonblank string Deviation and Consequence. Missing/null/numeric/blank/case-mismatched/duplicate/unknown properties and non-object payloads refuse rather than fabricate meaning. Parser failure retains an inner diagnostic while the public refusal uses application wording. Summaries require a recorded name and use recorded validated status counts. A blank stored safeguard is displayed as absent; counts do not certify safeguard sufficiency, investigation or closure approval.

Missing node/condition update targets now refuse. Invalid requested status or nonpositive identities cannot select another target. Generic persistence remains unavailable pending reviewed commands/transactions.

## Corrective-action interaction

The existing corrective-action owner also uses PROJECT. It must not accept an ID-matching HAZOP project as an existing corrective-action plan. CreateCAPlanAsync now verifies recorded CORRECTIVE_ACTION type and the existing PROJECT_NUM incident link before returning an existing ID. Reads/assignment/due-date/completion require a unique active typed plan with that recorded link before using steps. Missing assignment targets refuse and an empty action set cannot establish completion/deadline evidence.

This is a necessary guard on the shared PROJECT extension, not corrective-action readiness. CORRECTIVE_ACTION and PROJECT_STEP_BA authority remain unimplemented. The existing derived CA-ID/freeform incident-link convention still needs canonical relationship/storage/concurrency review through its owners; it confers no scope authority here. Actual corrective-action success remains unavailable pending that work.
