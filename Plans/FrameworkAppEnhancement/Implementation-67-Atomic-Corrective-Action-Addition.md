## Design and form audit

The four existing dialog fields are description, reference type, due date and responsible BA. The local beep-web/MudBlazor/UI-UX skill paths named by AGENTS.md were absent; the repository-parent skill search found no copies. The installed form-validation guidance was applied to this contract/required-input update; theme, branding, authentication and page styling were not changed. Previously a due date and type were silently supplied, BA was optional, the process request called it an app user, and action ID/sequence allocation occurred separately on every server attempt. The approved build extends the existing typed command and canonical row/reference policy. The Data-owned action request includes a stable caller ID and explicit description/type/UTC due date/recorded participant. No new persistence owner or migration is needed.

The dialog requires description, type, a chosen due date at explicitly labelled 00:00 UTC, and a recorded responsible participant. It allocates an intent ID when the dialog opens and retains it after an error. Submitting disables the submit/cancel buttons; success reloads the existing API view and closes the dialog. Failed or changed-payload retries preserve the same ID and require reconciliation or a new dialog intent. No new CSS/JS or authorization mechanism is introduced. Keyboard, accessibility, browser, reference-picker, durable circuit recovery and arbitrary regional cutoff/time-zone UX remain acceptance work.
