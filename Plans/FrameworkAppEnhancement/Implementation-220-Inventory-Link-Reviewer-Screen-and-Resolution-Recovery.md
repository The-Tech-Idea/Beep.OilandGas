# Implementation 220 — Independent reviewer screen and preparer resolution recovery

## Actionable procurement reviewer workflow

The existing procurement order screen now selects unresolved verified preparations by another account, displays complete independent source review, requires an explicit approve/reject selection and bounded single-line reason, and saves through the existing typed decision API. Approval applies the reviewed reference; rejection preserves it. The review panel shows original preparer/time/reason, current reference, target warehouse drill-down, recorded warehouse/location/unit, unknown on-hand quantity and source revisions. No approval is selected by default, and stock/financial effects remain unconfirmed.

Handlers require the current authenticated account to match the selected company account, an assigned standard app role, Procurement.View, Inventory.View and Procurement.RecordInventoryLinkDecision. The API independently enforces current app authority. Existing preparation, receiver and inventory-link review controls are disabled/guarded while an independent decision is busy or retains an unconfirmed intent. A later independent review invalidates an earlier receiver review. MudBlazor components reuse existing theming; no custom CSS/JavaScript, SQL, EF business path or frontend database access is introduced.

## Existing scoped owner and exact confirmation

PurchaseOrderWorkspaceState owns copied decision review/submission/result, busy state and original intent recovery route. Company/account/authentication/context/disposal changes invalidate displayed evidence while unconfirmed intent remains retained in that scoped owner. Review must agree with the complete displayed PO source revision and verified original target. Only another account's unresolved active preparation is eligible.

Recording freezes the original reviewer, decision, reason, canonical GUID intent and full source review before sending. Returned proof must agree with the exact original submission. A fresh complete owned-order read-back must match the returned line and reconstruct the original prepared-source revision when only the independently resolved line is replaced by its prepared preimage. Only then is an outcome displayed and the existing source projection refreshed. Unknown/failed/changed/absent/late results retain the original intent; retry ignores replacement form choice/reason and requires return to the original reviewer company/account/order. Circuit-scoped retention does not establish durable recovery after circuit loss.

## Read-only recovery of independently resolved preparation

A preparer with an unconfirmed preparation intent can now review its recorded independent resolution without resubmitting the already resolved preparation. The existing API adds POST `api/accounting/traditional/inventory/company/purchase-orders/{orderId}/lines/{lineId}/inventory-link-resolution` as a read-only source review carrying the original retained submission. It needs current standard app roles, Procurement.View and Inventory.View, not either mutation grant. The selected company/account, decoded resource and current PRODUCTION binding must match the original intent.

The shared Data resolution contract verifies canonical independent decision proof, exact original preparation command/full review and complete current owned source against the retained decision's prepared snapshot. Two actual source captures and closing complete role/grant/company/actor/binding comparison must agree. Missing/changed proof, different intent, changed binding/header or lost read authority cannot resolve the pending intent. The typed client freezes original context and validates the result. The scoped screen owner refreshes the confirmed order and clears pending status only after this validation; it displays the recorded independent outcome separately from preparation confirmation. This reads historical decision provenance; it does not assert current stock availability or create a new preparation/decision.
