## Desired workflow

The installation has a shared **system setup repository** in a database, managed through Beep Migration. It owns versioned system-wide PPDM/tool setup records and company-scoped environment records; it is addressed independently of a company's operational PPDM database. The existing authentication repository remains the owner of accounts and role/membership decisions. Shared definitions must be resolved for every user, with explicit company overrides and no cross-company global mutable state.

1. Detect repository installation/readiness without opening a domain database from the web client; distinguish migration, bootstrap, recovery and unavailable states. Guide the first administrator through the existing authentication owner.
2. Configure the tenant and select or create its company through existing authoritative membership and role flows. Select an exact company before company configuration; a persona never grants access.
3. Configure Beep connections, module targets, Beep Migration plan/approval/execution, reference data and failure/recovery using the existing API and module-database workflow. Never introduce SQL scripts for this feature.
4. For each authorized company choose an OilandGasTools country preset and review company-specific overrides: locale/time zone, units, coordinate systems, source mappings, code values, stratigraphy, tubular catalog, survey/tool models, toolboxes, labels and verification. Preserve all supported settings and versioned source provenance; country suggestions are not legal or operational approval. Never set a process-wide global environment for one company.
5. Verify administrator/company access, bindings, migration and seeding outcomes, environment loading and source coverage; provide explicit unavailable, failed and incomplete states and resume/repair. Completion is persisted only after actual checks; never infer completion from navigation or a client-side checkbox.
6. Provide first-start routing and authenticated administrator re-entry. Avoid blocking existing healthy deployments based on an unproven new marker. First-run/bootstrap and company setup are separate scopes.
