Delivery acceptance remains separate from price/unit compatibility, invoicing, recognition policy and ledger posting. No custom CSS, JavaScript, theme or direct frontend database access is introduced.

## Circuit-owned original intent

DeliveryAcceptanceWorkspaceState is scoped in Web and uses the existing commercial workspace ownership/reconciliation convention with delivery contracts. It freezes one preparation or decision and UUID before submission. Reload, failed acknowledgement, company/account/FIELD/transaction changes and component disposal clear displayed evidence but retain an uncertain original command. Matching original context can show retained facts/identity even when the latest read is unavailable. A pending command prevents a replacement proposal.

Fresh native read-back reconciles the exact preparation and recorded decision; it does not retry automatically. Absent unchanged evidence permits an explicit retry of the same original intent. Changed source, competing preparation/decision and different company/account/selection refuse retry and preserve uncertainty. Late results cannot refill a changed workspace. A superseded presentation owner cannot detach a newer owner. SDK acknowledgements are checked before read-back; the native business owner independently guarantees idempotency and committed evidence.

This state is retained within the current circuit/session. A delivery proposal that has not reached native persistence is not yet journaled for cross-circuit recovery. The screen tells the user to keep the session until reconciliation. Once persisted, the existing native envelope is authoritative. Durable unsent proposal recovery, acceptance correction/history and partial/shared-ticket workflows remain open; no general recovery completion is claimed.
