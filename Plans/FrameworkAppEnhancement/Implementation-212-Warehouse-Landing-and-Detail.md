# Implementation 212 — Company warehouse landing and item detail

## Persona screen delivery

The warehouse reviewer can open /warehouse from the existing procurement workbench or accounting dashboard when current standard app roles and Inventory.View are present. The new /warehouse/items/{Id} detail opens the exact recorded item ID from the landing queue. The page independently checks authenticated account identity, current selected-company roles and Inventory.View before calling its typed client. The API independently enforces current authority and full source/binding fences as described in Implementation 211. The page links receiving evidence and the shared assigned-task inbox without inventing receipt-to-stock relationships or task mappings.

InventoryWorkspaceState is the scoped owner of frozen scalar item/movement display projections. Its complete active-company item query can be restricted to a recorded warehouse and then to missing warehouse/location, unknown on-hand quantity or nonpositive on-hand quantity. Each displayed count applies the identical warehouse predicate and filters exact contributing rows. Queues may overlap; quantities and values are not aggregated across units or currencies. Only recorded warehouse values can be selected. Unknown source is unavailable; a successfully confirmed empty query has zero item counts. Recorded on-hand quantity does not establish available stock or replenishment approval.

Item detail retains recorded warehouse/location, quantity/unit, currency/unit cost/value/valuation, active status and creation/change audit. Complete active/inactive movement history retains original movement identity, type/date/quantity/cost/reference/notes and audit. Missing recorded values remain Unavailable. Source content revision and retrieval UTC are visible. Queue retrieval time is the client retrieval time, not a claimed database snapshot. Item detail uses the API review's retrieval time; no provider transaction is inferred from repeated capture.

Company/account changes, explicit clear, failed reload, disposal and authentication changes invalidate display and filters. In-flight old-context responses cannot publish. Detail company switches return to the warehouse landing. Malformed detail addresses clear source data and require reopening from the original queue. Reload busy/error/empty states reuse current MudBlazor patterns. Standard roles and app permissions govern navigation and loading; persona preference grants no rights.

## Shared architecture

Clients call the existing typed inventory API only. The shared Data contract and existing inventory/Beep repository owners remain authoritative. The Web host registers one scoped InventoryWorkspaceState. No parallel inventory model/store, database access, page-local theme, CSS/JS, SQL, EF schema path or live migration is added. No stock, receipt, reservation, supplier return, journal or financial approval write is introduced by the screen. Missing catalog validity and source linkage remain explicit evidence gaps.
