# 328 - Public recorded completion outcome

An authorized company user can now read the actual recorded completion outcome without the original reviewer's private decision command or recovery UUID. This closes a visibility gap between the independent reviewer and the operator/supervisor who needs the outcome before continuing work.

## Delivered workflow

- The existing completion evidence screen has a separate Read recorded decision outcome action, using the original process/report/order/FIELD identities. It works without Workflow.Approve and without independently verifying the reader's own work; a currently authorized original executor can read the outcome while remaining unable to decide their own work.
- The screen shows VERIFIED or REJECTED, the recorded reviewer account/native person/role, actual recording UTC, original report revision and approval/history identities. It explicitly distinguishes the recorded outcome from physical return acceptance and lifecycle advancement.
- A confirmed empty original decision population produces an explicit no-recorded-decision state. Missing source, schema, binding, authority, failed transport, changed original audit or changing observations produce errors/cleared evidence rather than inferred absence. Company/account/FIELD/auth/input changes and late replies retire visible state.
- Current standard app roles, Maintenance.VerifyCompletion, original FIELD/order WRITE, stored selection and CORE/lifecycle bindings are independently enforced by ApiService. This reuses the existing completion read boundary; it does not broaden grants or introduce IdentityServer authorization.
- PPDMProcessService reuses the original complete immutable approval/history/process proof, closes paired observations and projects public facts only. ApiService closes the original native physical report and recorded decision around repeated observations, verifying the original report revision and CORE binding. The public projection omits private rationale, retained command/body and recovery intent.
- The original reviewer can still use private recovery. Another authorized reader's public status access grants no private recovery and performs no workflow, physical, inspection, stock, cost or financial write.
