## Delivered planner workflow

The existing `/development/fdp` and `/development/fdp/new` page now opens the selected company's current FIELD, displays its recorded drafts, and lets an authorized planner enter a name, development description, planned first-production and field-life-end calendar dates, and optional CAPEX in millions with an explicit configured currency. Review shows those exact inputs before saving. View permission opens the list; Create permission and current FIELD WRITE authority admit creation. The API independently checks the authenticated account, authoritative app company roles/permissions and standard ASP.NET role bridge. No role, permission or currency is implicitly granted.

A save retains its immutable original input in ASP.NET protected session storage before transport, records one deterministic company/intent draft, then confirms its exact native readback. The tab session stores encrypted recovery input, never business records or authorization. Lost responses, failed confirmation or failed cleanup preserve the original for an explicit read-only outcome check. Reload can recover that same request. Company/account changes clear visible evidence; FIELD/core/planning binding changes prevent recovery under replacement resources. No automatic retry or new-intent substitution occurs. A confirmed absence allows a new reviewed save; changed/inactive/moved/foreign/ambiguous originals cannot become false absence.

Saving records DRAFT version 1 and the actual maker/UTC creation audit. It does not submit, approve, book reserves, reserve a rig or change an operating well. Those are subsequent company persona workflows.
