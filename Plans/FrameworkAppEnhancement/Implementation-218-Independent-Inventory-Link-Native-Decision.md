# Implementation 218 — Independent native inventory-link decision and reference application

## Independent reviewer behavior

The existing PurchaseOrderService now records an independent inventory-link decision against the retained preparation on the original owned PO line. Approval atomically changes INVENTORY_ITEM_ID to the originally reviewed owned target and records decision/audit proof. Rejection records the decision while preserving the current reference. Both preserve the original preparation JSON exactly; neither changes receipts, inventory quantities/movements, AP, journal or financial approval.

Shared Data contracts require an explicit Approve/Reject enum, bounded reviewer/IDs/reason, canonical GUID intent, original company/binding and complete decision review. The reviewer must differ from the original preparer and cannot be SYSTEM. The review validates canonical original preparation, reconstructs its original full PO source, and requires the original target inventory/movement revision and binding to remain unchanged. An already resolved line, forged preparation/audit, changed source/target/binding, missing original proof or undefined decision refuses. Changed evidence requires a future reviewed supersession path; it cannot be silently accepted by this original-intent decision method.

## Existing owner, transaction and retained evidence

The new method uses the existing request-bound datasource/repository and an owned Serializable Beep transaction. Its mandatory trusted authority callback is evaluated before and throughout source capture, mutation and confirmation. Global line identity must be unique and agree exactly with the owned order. A narrow original-line row policy permits only its reviewed update, applies a target reference only for Approve, and verifies canonical proof after common UTC audit preparation. It cannot grant general reads, insert/delete, alter another line or change unrelated original line/proposal data.

Exact command/full-review retry verifies the retained decision and adds no writes. Failed/corrupt writes roll back. Unknown commit and post-commit target drift produce no confirmed result; restoring original evidence permits exact original-intent reconciliation. Confirmation compares complete source and target revisions, canonical proof, exact stored line and pre-/post-commit read-back. Live provider isolation/locking is not established by these fixture tests.

PO_LINE_ITEM adds nullable INVENTORY_LINK_DECISION_JSON with a 1048576-character bound. The decision retains the complete prepared source and inventory target, including original proposal JSON; its larger bound avoids making ordinary large valid preparations impossible to resolve merely because evidence is retained again. An explicit large-evidence test confirms a decision larger than the preparation column bound without truncating its 140000-character recorded target description. Over-bound evidence still refuses. Fresh physical schema/type/nullability/bound are required before mutation through Beep MigrationManager metadata; no live migration, SQL or new EF business path is added. The existing canonical module manifest owns the PO line. Null decision fields preserve the earlier unprepared serialization/source digest shape; retained decisions participate in current source revision.

Canonical preparation proof reads on resolved lines validate the complete independent decision and recover the original prepared preimage. This preserves preparer attribution without pretending reviewer change audit was preparation audit. The preparation command refuses a resolved line, preventing an independently applied link from being returned as a newly unchanged preparation. Subsequent preparation/decision cycles remain unimplemented; retained evidence is not destructively replaced.

## Existing source display and permissions

The existing PO projection and source panel display verified original preparer actor/time/reason separately from independent reviewer decision/actor/time/reason. Approval/rejection and the current reference are shown from canonical retained evidence; malformed decision evidence is explicitly unconfirmed. Stock and financial effects remain unconfirmed. The existing receipt-to-inventory review accepts an approved reference with its unchanged canonical receiver proof, and an integration check verifies this native source behavior without additional stock/receipt writes. Existing PO/receiver/AP-to-PO inventory-evidence read permission checks also cover non-null decision evidence.

This slice is the native decision/application owner and existing source display, not an exposed decision API or actionable reviewer screen. The mandatory authority callback is tested as a boundary; actual current app roles, independent decision grant, API endpoint/client enforcement and reviewer save/recovery controls remain the next integration. IdentityServer stays authentication-only. No permission provisioning is performed.
