# Company permit application workflow

Owner: [master tracker](Company-Plan-Index.md), [HSE persona](Persona-09-HSE-and-Compliance.md) and [feature 09](Feature-09-Governance-and-Durable-Workflow.md), implementation step 2.

## Outcome and phases

The HSE/compliance account opens a current company/FIELD application, inspects recorded application/history and explicit checker evidence, then uses reviewed submission and independent decision commands with retained originals and verified persisted outcomes. The complete feature is not a read-only destination.

1. Focused verified: canonical Data-owned transport contracts, explicit native-to-wire mapping, exact identity reads and authenticated company/FIELD detail/reload. Remove duplicate Web/API transport classes and raw native detail payloads. No schema change.
2. Implement current app permission/native company/resource authority and reviewed, recoverable submission/independent decision owners. Replace old direct mutation routes/clients in the same slice; no compatibility owners. Bind explicit country/authority, current source revisions, reason, actor independence and exact audit/readback. Use Beep Migration only for necessary new data classes.
3. Connect retained sender/reviewer forms, next-role inbox/landing, outcomes and correction/rejection. Require real current application authority; never record Environment.UserName as the business actor.
4. Qualify focused protected HTTP/provider/browser/two-company collisions/reload/lost acknowledgement and regional policy evidence. No assumed legal approval, deadlines or jurisdiction compliance.
