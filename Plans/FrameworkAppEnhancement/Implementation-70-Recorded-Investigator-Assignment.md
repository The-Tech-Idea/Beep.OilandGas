## Actual owner and behavior

The existing HSEIncidentService.AssignInvestigatorAsync overwrote participant identity in place and used an active-only maximum observation allocator. Generic HSE mutation was fenced, so the existing controller/facade route could not safely persist assignment. The legacy mutation and allocator are removed. The existing incident owner now delegates to a Data-owned ICompanyIncidentCommands contract, independently enforced by ApiService's PPDMCompanyIncidentCommands through the existing company/case/participant policy, PPDMGenericRepository and owned PPDMDataSourceTransaction lane. Reads remain available without a command dependency; assignment explicitly refuses when it is absent. There is one investigator write path.

Assignment accepts the BA identity of a unique current **already recorded case participant**. An arbitrary existing BUSINESS_ASSOCIATE is insufficient to create a party or infer personal identity. Exact case role/status vocabulary, UTC current reference/incident-state evidence, active company HSE.View/HSE.ManageIncidents, recorded case restrictions and their reviewed interpretations, actual inherited current FIELD write grant and FIELD data entitlement are required. The current selected FIELD, actor/company and physical database review are checked independently by the command. Assignment preserves all five existing nonterminal workflow stages: REPORTED, UNDER_INVESTIGATION, PENDING_RCA, PENDING_CORRECTIVE_ACTION and PENDING_CLOSE_OUT. Unknown, closed, cancelled, expired/future or ambiguous state refuses. A command does not move the case to another stage. The command does not normalize free text or manufacture reference records.

Existing participant reference checks are extracted within CompanyPPDMRowAccessPolicy and reused by both stored roster and prepared assignment validation. Full participant/company/crew/period/WELL evidence remains the existing owner. Current case authority captures the header, all active component/restriction definition evidence and configured case read interpretations. FIELD grant identities/revisions and state/reference/FIELD snapshots are captured and rechecked, including closing stored-state reads after dependent awaits.

New investigator role observations preserve the participant's actual PARTY_OBS_NO and recorded identity/company/crew context, and allocate PARTY_ROLE_OBS_NO after **all** same-party history including inactive observations. Reassignment retires the exact previous full three-column key with the same UTC instant as the new assignment's effective date. It preserves the previous identity and other party roles; it does not rewrite a witness/participant identity. Recorded role remarks stay on their original role observation; the new investigator row has no fabricated or copied role statement. The actual current investigator must be unique. Repeating the same current target validates the recorded ASSIGNED status and performs no new write.

Both retirement and insertion require one owned physical Serializable Beep transaction. Private one-use mutation policies allow only the exact prepared row and original snapshot, current command/reference authority and real common-column audit preparation. Generic participant writes remain unavailable. Complete roster/audit/history is compared inside the transaction and after commit. Provider OK without the exact persisted effect refuses; failures roll back. Lost commit acknowledgment requires evidence reconciliation; same-current-target retry is verified by the focused command tests.
