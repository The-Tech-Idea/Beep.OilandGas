## Canonical data and API boundary

`REVENUE_TRANSACTION` is moved from ProductionAccounting into TheTechIdea.Data, preserving its existing namespace, native property names and public shape. There is one source definition; the existing native identity is marked as the key. The canonical `FieldRevenueSourceReview` captures company, account, FIELD, exact window, binding and a digest of the complete copied native graph. It rejects malformed/duplicate identity, inactive or out-of-window rows, conflicting FIELD/property association and changed scope or payload. Nullable recorded facts are preserved.

The existing ProductionAccounting service gains a native generic-repository reader. It requires the exact native primary key, reads both PROPERTY_ID and FIELD_ID membership, uses an exclusive next-day upper bound to include the final day's later transactions and merges identical overlap only. It refuses untyped rows, ambiguous duplicate identities and changed datasource identity. It does not truncate or use a first-nonempty association fallback.

`GET /api/fields/{fieldId}/accounting/revenue-source?from=yyyy-MM-dd&through=yyyy-MM-dd` uses the existing fresh company/module read context and independently checks authentication, an authoritative company role matching the principal's standard ASP.NET role, Accounting.View and exact FIELD READ. Authority, PRODUCTION connection/binding and source graphs are recaptured before returning. Revoked authority refuses access; changed source refuses publication. These sequential checks detect observed drift and do not establish a database transaction snapshot.

The existing production registration supplies ProductionAccountingService and maps ICompanyAccountingReadContext to CompanyModuleConnection. The new orchestration registration uses those owners. Native company authority and real-provider completeness remain wider acceptance gates: native transactions carry FIELD/property associations rather than new company ownership fields. This slice relies on the established selected-company context, asset-access owner and tenant-owned module binding; it does not claim a new native per-company revenue ownership proof.

The typed client escapes the exact FIELD route ID and verifies the returned canonical scope, actor, window and digest against its original company snapshot. The Razor page verifies selected account and standard role before reading, clears evidence on company/FIELD/authentication changes and discards late results. Loading, missing company/FIELD, denied/failed and confirmed-empty states remain distinct. A failed read never becomes a zero KPI. Retrieved UTC is a client receipt time, not a posting or recognition date.
